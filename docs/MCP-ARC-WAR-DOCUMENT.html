01 The enemy

Sprawl, invisibility, and provider-name masquerade

Andromeda's charter isn't abstract idealism — it's a list of specific, measured messes on the Studio host. Three of them are the whole war:

① MCP sprawl — the invisible process tax

Every agent host — Cursor, Claude Code, Codex, Hermes — boots its own MCP servers via npm exec. No shared registry, no dedupe, no roster. The 2026-07-15 Studio snapshot: 60 npm exec parents, including 15× filesystem, 15× memory, 15× sequential-thinking, each ~71 MB in Activity Monitor. Config for the same servers is scattered across ~/.cursor/mcp.json, Claude Desktop, ~/.claude.json, Codex config.toml, and the Hermes VM — with no source of truth.

② The masquerade — a multica MCP that never talks to Multica

The multica entry in ~/.claude/settings.json doesn't reach Multica at all. It boots OMC's 31,908-line, 1.1 MB mcp-server.cjs — MULTICA_SERVER_URL is referenced zero times. A provider name on a config key, hiding a giant Node blob. This is exactly what the charter's non-negotiable 8 forbids: "Capability names beat provider names."

③ Invisible daemons — launchd with no roster

The charter's second non-negotiable: "No invisible launch agents, watchdogs, or hidden daemons." The sprawl doc names this a parallel problem class → the planned LaunchEntity. On 2026-08-04, ~36 KeepAlive jobs were swept into a quarantine folder by hand, with no roster and no alerting — and nobody noticed until a memory service started returning 502 eleven days later.

02 Field intel — reconnaissance run, 2026-08-15

Today wasn't firefighting. It was reconnaissance across all three fronts.

Each incident resolved today is a live, dated data point proving the enemy above is real and load-bearing — not a slide-deck abstraction.

Proved multica MCP ≠ Multica, live. The MCP wrapper 500'd on every write. The real Multica turned out to be a healthy native PG17 stack (:5442 / backend :3637) with nothing to do with the MCP name — the outage was a DB counter drift (issue_counter 257 vs. max(number) 289). Repaired; ticket filed as HAB-290. The name lied; the plumbing was elsewhere.
Front ③invisible daemons
Audited the 2026-08-04 launchd quarantine. 36 jobs, no roster. 13 already covered, 6 down-and-wanted (incl. vault-backup — dark for 11 days), 5 verify, 12 leave-disabled. This is the LaunchEntity / Fleet-Runtime pillar's exact justification, produced as evidence.
Front ①memory fabric
Anima (pillar 1) was down behind a live proxy. The vault-sync relay returned 502 — Tailscale Serve was up, its upstream relay dead (swept in the same quarantine). Restored under launchd; the iOS pull bug ("Parent folder doesn't exist") fixed in plugin v0.1.1 and shipped to the phone. A "thin HTTP door until Andromeda hosts it natively" — which is the point.
Front ②the blob
Pulled OMC out of the terminal welcome. Small cut, same body: OMC is the very 31,908-line bridge PR #46 exists to retire. Every place it surfaces is a place the Swift-native replacement will own.
03 First strike — the landing party

PR #46 — AndromedaMCP: 819 lines of Swift against a 31,908-line blob

feat/andromeda-mcp MERGED · 2026-08-15

The first Andromeda-managed MCP server: a Swift 6 package with zero SwiftPM dependencies (Packages/AndromedaMCP) exposing code.search and code.replace over MCP stdio (JSON-RPC 2.0, line-delimited) — capability IDs; the ast-grep engine behind them stays behind the server boundary. ~819 lines of typed Swift + 485 lines of tests that drive the real built binary over stdio with parallel-safe fixtures. macOS 14+, Swift 6 language mode. One runtime prerequisite: the ast-grep engine (brew install ast-grep), discovered by EngineLocator at boot — without it the server still serves initialize/tools/list and reports the gap per tool call.

✓ Build & Test (macOS) · ✓ Cursor Security Reviewer · +2,952 / −1 across 37 files · also lands the swift-skill canon (21 reference files) and AndromedaStatusline. Follow-ups (id echo, CI truth, drain regression) landed same-day in #47. Diff-tested against a live exchange: APPLIED: 1 replacement — print("old") → logger.debug("old"), file rewritten on disk.

Craft, per the canon: ast-grep output decoded into a typed Decodable model (no JSONSerialization casting); the dry-run/writer two-pass documented and covered by tests. This is the charter's Definition of Done, not a spike.

06 Rules of engagement — the non-negotiables

Why the Swift rewrite isn't optional

No silent loss. No invisible automation. No provider lock-in disguised as configuration. No knowledge without provenance. No automation without visibility. No migration without rollback. — Andromeda Charter, Core Promise
  • No Bash implementation surface. Behavior lives in Swift modules and typed CLIs — shell only as documentation.
  • No invisible launch agents. Background work must appear in a command bar, menu bar, or console.
  • Everything observable. Structured logs, owner, failure class, privacy class on every operation.
  • Append before processing. Observations are journaled durably before enrichment or routing.
  • Human authority explicit. Observation ≠ suggestion ≠ reversible ≠ destructive ≠ privileged.
  • Capability names beat provider names. The multica-that-isn't-Multica is the anti-pattern in one word.

The through-line: today's three fires all trace to the same root — configuration pretending to be a system. A key named for a thing it isn't; a proxy over a corpse; a folder of daemons nobody can see. Andromeda's answer is not more config. It's a control plane that makes all of it a typed, observable, replayable Swift entity. PR #46 is where that answer stops being a charter and starts being a binary.
